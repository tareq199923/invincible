Hosted setup

Start with your account and your credentials

Use the hosted service at invincible-ai.me. You do not need a local PostgreSQL database, environment file, or server process to route chat through Invincible.

01

Create an account

Register with email and password, or sign in with GitHub when your deployment enables it. Your account owns its keys, providers, sessions, and state.

/register
02

Connect providers

Choose a provider from the catalog or add any OpenAI-compatible Chat Completions endpoint. Each key is encrypted at rest and used only for your account's requests.

dashboard → providers
03

Create an API key

Generate a per-user inv_ key from Account. The raw value is shown once, stored as a hash, and can be revoked immediately.

dashboard → account → API keys
04

Connect your client

Point an OpenAI-compatible client, Claude Code, or Codex at Invincible. Use the separate MCP endpoint only when your client supports OAuth tools.

Continuity and control

The pieces agent workflows need to keep working

Provider choice stays replaceable. Your account, projects, credentials, memory, and continuity state remain attached to Invincible.

Per-user BYOK failover

Choose auto, pinned, or chain routing. Invincible tries the next available credential after rate limits, server errors, network failures, or disabled authentication—without claiming to optimize for price.

Versioned continuity

Task state is updated with optimistic version checks, immutable checkpoints pin important states, and a pre-switch checkpoint can capture the provider failure before failover continues.

Scoped lexical memory

PostgreSQL stores memories with layer, confidence, provenance, and project scope. Lexical retrieval combines full-text relevance, recency, kind, confidence, and a bounded top-N result set.

OAuth-protected MCP tools

Ten tools cover file reads, approved shell execution, approved writes, task state, checkpoints, and memory. execute_bash and write_file require a single-use confirmation token.

Paired machine execution

When the hosted deployment routes tool jobs to your paired agent, confirmed commands and writes execute on your machine inside a home-relative sandbox. Reads and data-plane tools do not use that second approval.

Usage and run history

The dashboard aggregates attempts, failovers, and input/output token counts by day and provider/model. Provider-attempt history and continuity projections show how tracked work moved forward.
